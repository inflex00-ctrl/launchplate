Changelog

Every change we ship, written by the people who shipped it. We release roughly every two weeks and never quietly remove anything.

Subscribe via RSS API versioning policy

14 August 2026

v4.2.0 Latest

NewImprovedBreaking

Signals v3 — continuous evaluation

Signals no longer wait for a nightly job. Every account is now evaluated against every active condition as events arrive, with a median firing latency of 1.8 seconds. This is the largest change to the evaluation engine since launch, and it is live for every workspace.

New

Streaming evaluation. Conditions are checked as events land rather than on a schedule. Nightly evaluation remains available for signals that depend on billing state, which still settles daily.

New

Signal backtesting. Before activating a signal, replay it against the last twelve months of history to see how often it would have fired and against which accounts.

New

Firing explanations. Every firing now links to the specific events, thresholds and time windows that produced it. Available in the UI and on the API as explanation.

Improved

Signal editor now shows the compiled SQL for any condition built in the visual builder, so your data team can review rather than rebuild.

Improved

Throttle configuration moved to the signal level, with per-channel overrides. The old workspace-wide throttle is migrated automatically.

Breaking

The signals.evaluated_at field is deprecated in favour of signals.fired_at. The old field continues to return values until 1 February 2027.

29 July 2026

v4.1.0

NewImprovedFixed

Reverse ETL is generally available

Push scores, segment membership and signal history back into Snowflake, BigQuery, Redshift or Postgres on a schedule you control. Available on Scale and Enterprise plans after four months in private beta with 60 customers.

New

Reverse ETL destinations. Write account_scores, segment_members and signal_events back to a schema you nominate, with full-refresh or incremental modes.

New

dbt source generation. Northwind emits a sources.yml for the tables it writes, so downstream models pick them up without hand-editing.

Improved

Warehouse sync now supports key-pair authentication for Snowflake in addition to username and password.

Improved

Sync failures now surface the underlying warehouse error rather than a generic message. Long overdue.

Fixed

Fixed a case where a sync that timed out mid-batch could double-count events for accounts whose IDs sorted last.

8 July 2026

v4.0.0

NewBreaking

Composite health scoring

Health is now a weighted composite of adoption depth, feature breadth, support sentiment and billing health, rather than a single usage number. Existing scores are preserved under the name Usage score.

New

Composite scores. Define your own weights across four component dimensions, or start from one of three templates for PLG, seat-based and usage-based businesses.

New

Score history. Every account keeps a daily score series for two years, so you can chart the slope rather than argue about the number.

New

Cohort comparison. Compare score distributions between two segments to test whether an onboarding change actually moved retention.

Breaking

account.health_score now returns the composite score. Your previous values are available as account.usage_score with no change in definition.

24 June 2026

v3.9.2

SecurityFixed

Security hardening and session controls

Our annual penetration test closed with no critical or high findings. Two medium findings are addressed here, along with new session controls requested by several Scale customers.

Security

Configurable session lifetime from 1 hour to 30 days, set per workspace. Idle timeout is now independent of absolute timeout.

Security

Session tokens are now rotated on privilege change, so a role downgrade takes effect immediately rather than at next login.

Security

Tightened the CSP on the application shell and removed the last two inline script exceptions.

Fixed

Audit log export could omit entries from the final minute of the selected range. Fixed and backfilled for all affected workspaces.

3 June 2026

v3.9.0

NewImproved

Playbook approval steps

Automation is only useful if you trust it. Playbooks can now pause for a human before anything reaches a customer, with the draft, the reasoning and the account context in one review screen.

New

Approval steps. Insert a review gate anywhere in a playbook. Approvers are notified in Slack and can approve, edit or reject inline.

New

Draft editing. Generated emails can be edited before sending, and edits feed back into the template so the next draft is closer.

Improved

Playbook runs now show a full execution trace with timing for each step, which makes debugging a stalled play far less mysterious.

Improved

Quiet hours are now timezone-aware per recipient rather than per workspace.

19 May 2026

v3.8.1

ImprovedFixed

Faster account search and timeline loading

A round of performance work aimed at the two screens people open most. Account search is now roughly six times faster at the 95th percentile, and timelines render progressively instead of blocking.

Improved

Account search moved to a dedicated index. P95 query time dropped from 1,240ms to 190ms across all workspaces.

Improved

Timelines stream in reverse chronological pages rather than loading the full history before first paint.

Improved

Reduced the application bundle by 38% by removing a charting dependency we were using for exactly one sparkline.

Fixed

Timeline entries from Zendesk could appear with the ticket creation time rather than the event time when the two differed across a day boundary.

Fixed

Keyboard navigation skipped the filter bar on the segments screen for Safari users.

28 April 2026

v3.8.0

NewImproved

EU data residency for every plan

Choose Frankfurt or Virginia when you create a workspace. Residency now applies to event storage, backups, search indexes and logs — and it is included at no extra charge on every paid plan, not only Enterprise.

New

Per-workspace residency. Selected at creation and immutable afterwards, so there is never ambiguity about where a record lives.

New

Sub-processor notifications by email and RSS, 30 days before any change takes effect.

Improved

Data export now includes a machine-readable manifest listing every table, row count and checksum.

2 April 2026

v3.7.0

NewFixed

HubSpot two-way sync

HubSpot joins Salesforce with full two-way synchronisation: read company and deal properties into signals, write scores and signal events back onto the company record.

New

HubSpot two-way sync with field-level mapping and conflict rules you configure rather than inherit.

New

Deal-stage signals. Trigger on usage changes within an open opportunity, which turns out to be the single most requested signal we have shipped.

Fixed

Salesforce sync no longer retries indefinitely on a permanently invalid field mapping. It now fails loudly after three attempts and tells you which field.
